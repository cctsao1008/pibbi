# pibbi ESP32-S3 Firmware

This pibbi-owned ESP-IDF project compiles the full Seeed factory firmware
implementation from third_party/SenseCAP-Watcher-Firmware without editing
its source checkout. The build wrapper creates an ignored, reproducible
vendor_overlay/main tree and applies guarded source corrections there.

## Build and flash

From the pibbi repository root:

```powershell
.\tools\esp32s3\build.ps1
.\tools\esp32s3\flash.ps1 -Port COM31
.\tools\esp32s3\monitor.ps1 -Port COM31
```

The build wrapper selects this project by default (-Example pibbi). The
unmodified vendor application can still be built with -Example factory_firmware.
COM31 is the observed W1-A ESP32-S3 port on one Windows installation.

## Integration

- main/CMakeLists.txt compiles the original Seeed factory application sources.
- Only the upstream main.c translation unit remaps app_sensor_init at compile
  time to pibbi_app_sensor_init; no third_party source is modified.
- main/pibbi_startup.c first calls the original Seeed app_sensor_init, then
  starts pibbi's sensor service.
- components/pibbi_sensors reuses the Watcher BSP I2C bus (SDA GPIO47,
  SCL GPIO48) and maintains an inventory of Waveshare Environment Sensor HAT
  endpoints: 0x68, 0x76, 0x29, 0x53 and 0x59.
- Device-set changes publish PIBBI_SENSOR_PRESENCE_CHANGED via
  PIBBI_SENSOR_EVENTS; consumers can also use pibbi_sensors_get_presence().

The sensor presence event is an operational device inventory, not a sensor
measurement. Driver integration, observation transport and the LSMM adapter
are the next application features.

The factory Kconfig, default sdkconfig, partition layout and component
dependencies are mirrored to preserve upstream compatibility. Continue
using app-only flashing; keep nvsfactory and all credentials private.

## Upstream warning corrections and clean build

The script tools/esp32s3/prepare-vendor-overlay.py copies upstream main
sources and applies guarded, narrowly scoped corrections to vendor code,
without changing third_party or committing a second vendor source fork.
The copy is ignored by Git. It retains existing source timestamps when
bytes are unchanged, supporting ordinary incremental builds.

Corrected classes include invalid API argument types, MP3 sample buffer
allocation, source-format warnings, LVGL autogenerated unused variables,
deprecated SNTP calls and redundant BLE definitions. Other vendor warnings
remain visible until explicitly corrected; no new warning suppression flags are introduced; upstream compiler
options are unchanged.

For a genuine clean build after updating:

```powershell
git pull --ff-only
.\tools\esp32s3\build.ps1 -Clean
```

This removes the configured build output and recompiles against the
freshly prepared overlay. It does NOT erase or flash the device.

## pibbi face (v0.1 — first firmware increment)

The 2D white-bear UI follows the approved reference board (no fur or
photorealistic assets). On the original Watcher Home page, an independent
`pibbi_face` LVGL component renders the bear using small, flat shapes.
This is **not** a full-screen bitmap; eyes, mouth, and cheeks can change
individually. The component offers `pibbi_face_set_expression()` for
future camera, audio, and behavior-state integration.

- **On Home:** bear appears in place of the factory Home widgets.
- **Idle:** slow eye movement and periodic blinking.
- **Tap:** brief happy expression.
- **Long-press bear:** expose the unchanged factory Home / Settings menu.
- **Tap “pibbi” on factory Home:** return to the animated face.
- **Factory onboarding:** the original Connect / Skip page remains available
  before the Home page is reached on an unconfigured Watcher.

The LVGL UI must only be modified while holding the LVGL port lock, or from
an LVGL event/timer callback. This first increment does not yet route the
knob, Camera, voice, or AI state into the face.

Verification: `./tools/esp32s3/build.ps1 -Clean` (PowerShell), then
application-only flash with `./tools/esp32s3/flash.ps1 -Port COM31`.
Hardware validation is required; this implementation has not been flashed
as part of the GitHub change.
